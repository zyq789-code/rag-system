## RAG（检索增强生成）原理与完整流程

### 为什么需要 RAG
- LLM 只有训练时知识，回答私有/最新问题时容易幻觉
- RAG 先检索相关知识，再让 LLM 基于知识回答 → 可溯源、可更新、降低幻觉

### 离线索引阶段（一次构建）
1. 文档解析：PDF/DOCX/TXT 提取纯文本
2. 分块：长文本切分（按 token 数，如 512 + 重叠 64）
3. 向量化：Embedding 模型把每个块转成向量（如 BGE-small 512 维）
4. 入库：向量写入向量数据库（ChromaDB/FAISS/Milvus）

### 在线问答阶段（每次请求）
1. 用户问题向量化
2. 检索：向量相似度召回 Top-K + 关键词（BM25）召回
3. 融合重排：RRF 融合 + Cross-Encoder 精排 Top5
4. 拼 Prompt：系统提示 + 带来源的上下文 + 历史对话 + 问题
5. LLM 流式生成，回答附带引用来源

### 关键设计点
- 混合检索：向量召回语义相似、BM25 兜底精确关键词
- 引用溯源：让回答"有据可查"，用户可核对
- 无答案处理：上下文不相关时明确告知，不硬编

> 面试延伸：RAG vs 微调——RAG 适合知识频繁更新、追求可溯源；微调适合改变模型风格/领域能力。
