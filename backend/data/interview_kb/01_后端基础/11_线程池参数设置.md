## 线程池的核心参数与如何设置

### ThreadPoolExecutor 七个参数
- **corePoolSize**：核心线程数，常驻
- **maximumPoolSize**：最大线程数
- **keepAliveTime**：非核心线程空闲存活时间
- **workQueue**：阻塞队列
- **threadFactory**：线程工厂（命名、守护线程）
- **handler**：拒绝策略（Abort / CallerRuns / Discard / DiscardOldest）

### 执行流程
1. 线程数 < corePoolSize → 新建线程
2. ≥ corePoolSize → 入队
3. 队列满 且 线程数 < maximumPoolSize → 新建非核心线程
4. 都满了 → 拒绝策略

### 参数怎么定（经验值）
- **CPU 密集**：`线程数 = CPU 核数 + 1`
- **IO 密集**：`线程数 = CPU 核数 * (1 + 等待时间/计算时间)`，或 `CPU 核数 * 2`
- 队列容量：根据峰值积压量和可接受延迟估算
- 拒绝策略：核心业务建议 CallerRunsPolicy（调用方线程执行，天然限流）或自定义告警

### 常见坑
- `Executors.newCachedThreadPool()` 队列是 SynchronousQueue，任务多时疯狂建线程 → OOM 风险
- 记得给线程命名，方便排查

> 面试延伸：线上"提交任务被拒绝"如何处理——要么调队列/线程数，要么改拒绝策略为告警 + 落库重试。
