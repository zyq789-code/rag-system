## MySQL 事务隔离级别与 MVCC

### 四个隔离级别
| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| 读未提交 | 有 | 有 | 有 |
| 读已提交 | 无 | 有 | 有 |
| 可重复读（默认）| 无 | 无 | 有（InnoDB 用间隙锁解决）|
| 串行化 | 无 | 无 | 无 |

### MVCC（多版本并发控制）
- 每行记录带隐藏字段：`trx_id`（修改它的事务 id）、`roll_pointer`（指向 undo log 旧版本）
- 事务开始生成 **read view**（活跃事务列表）
- 读操作通过 undo log 版本链 + read view 判断可见版本 → 读不加锁，写不加读锁

### 当前读 vs 快照读
- 快照读（普通 SELECT）：走 MVCC，不加锁
- 当前读（SELECT ... FOR UPDATE / UPDATE / DELETE）：读最新版本并加锁

### 可重复读如何避免幻读
- 快照读：MVCC 天然避免
- 当前读：`next-key lock`（记录锁 + 间隙锁）锁住区间，阻止插入

> 面试延伸：MVCC 就是"读不加锁、写不阻塞读"，是 InnoDB 高并发读性能的核心。
