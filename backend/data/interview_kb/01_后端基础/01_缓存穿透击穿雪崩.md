## 缓存穿透、击穿、雪崩的区别与解决方案

### 缓存穿透
**现象**：查询缓存和数据库都不存在的数据，请求直接打到底层数据库。

**方案**：
- 布隆过滤器：把可能存在的数据 hash 到 bitmap，不存在则直接拒绝
- 缓存空值：查询为空也缓存一份，TTL 设短（如 60s）

### 缓存击穿
**现象**：某个热点 key 在过期的瞬间，大量并发请求同时打到数据库。

**方案**：
- 互斥锁（setnx）：只有一个线程去查库并回填，其余等待
- 逻辑过期：key 不物理过期，在 value 里存过期时间，异步刷新

### 缓存雪崩
**现象**：大量 key 同时失效，或缓存服务整体宕机，请求洪峰直达数据库。

**方案**：
- 过期时间加随机值：避免大规模 key 同时到期
- 多级缓存：本地缓存 + Redis 双层
- 限流降级：网关限流、熔断降级保护数据库
- 高可用：Redis 集群 + 主从

> 面试延伸：穿透是针对"不存在的数据"，击穿是"单个热点 key"，雪崩是"大规模同时失效"——三者的核心区别和对应策略要能脱口而出。
