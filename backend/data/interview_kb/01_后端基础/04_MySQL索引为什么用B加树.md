## MySQL 索引为什么用 B+ 树而不是别的结构

### 为什么不用哈希索引
- 哈希只支持等值查询（O(1)），不支持范围查询、排序、前缀匹配
- InnoDB 自适应哈希索引只作为 B+ 树的加速

### 为什么不用二叉搜索树 / 红黑树
- 树太高：一个节点只有 2 个孩子，存储几百万数据需要几十层，每层一次磁盘 IO
- 磁盘 IO 是瓶颈，树高 = IO 次数

### 为什么用 B+ 树
- **矮胖**：一个节点（页，默认 16KB）能存上千个 key，树高 2~3 层即可覆盖千万级数据
- **范围查询友好**：叶子节点用链表串起来，`BETWEEN`/`>` 顺序扫描高效
- **查询稳定**：所有数据都在叶子节点，查询路径等长
- 非叶子节点只存 key 和指针，不存数据，页能放更多 key → 树更矮

### 相关概念
- 回表：二级索引查到主键后，再回主键索引取整行数据
- 覆盖索引：查询的列都在索引里，无需回表
- 最左前缀：联合索引 (a,b,c) 查询条件必须从 a 开始才能命中

> 面试延伸：为什么表要有主键？因为 InnoDB 主键索引（聚簇索引）叶子节点存整行数据，主键就是表的物理组织方式。
