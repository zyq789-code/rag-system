## 一、检索质量类

### 1. 英文重排模型对中文打分失效（最关键的坑）

**现象**：向量检索和 BM25 都把正确文档排第 1，但重排后正确文档被挤出 Top-5；评测 hit@1 仅 63.6%。

**根因**：`cross-encoder/ms-marco-MiniLM-L-6-v2` 是英文模型，中文经其 tokenizer 大部分变成 `[UNK]`，对任意中文对打分近似恒定（实测 7.37~7.66 挤在一起），重排不仅无益反而破坏排序。

**解决**：换成中文优化的 `maidalun1020/bce-reranker-base_v1`，hit@1 63.6% → 100%。

**预防**：模型语言必须与语料匹配；用评测（hit@k/MRR）而不是肉眼判断。

---

### 2. BM25 中文不切词

**现象**：中文整句被空格分词当成一个 token，关键词检索几乎失效（hit@1 仅 12.5%）。

**根因**：`rank_bm25.BM25Okapi` 默认空格分词，对无空格中文退化为整句匹配。

**解决**：jieba 中文分词 + 基础停用词过滤。

**预防**：中文检索必须分词；写分词单元测试。

---

### 3. top_k_bm25 配置未生效

**现象**：`TOP_K_BM25=20` 从未生效。

**根因**：代码误用 `settings.top_k_vector` 而非 `settings.top_k_bm25`。

**解决**：改用 `top_k_bm25`。

**预防**：配置项与代码引用要一一核对。

---

## 二、分块类（来自代码审查）

### 4. 双换行压单换行，丢失段落结构

**现象**：`text.replace("\n\n", "\n").split("\n")` 把段落边界抹平，制度文件/技术文档切分粒度变粗。

**解决**：保留 `\n\n` 作为一级分隔符，先按结构单元切分（段落/标题/代码块/表格）再贪心累积。

---

### 5. overlap 用字符估算而不是数 token

**现象**：`current_chunk[-chunk_overlap*4:]` 用「4 字符≈1 token」估算，中文实际 1 字≈1 token，overlap 偏大。

**解决**：用 tiktoken 精确取末尾 N 个 token：`encode → tokens[-N:] → decode`。

---

### 6. 表格/代码块/标题无针对性处理

**现象**：按行切会把表格拆散；代码块/公式可能被拦腰切断；标题层级（H1/H2/H3）没利用为切分点。

**解决**：标题（`#` 开头）作天然切分点；代码块（``` 围栏）、表格（`|` 行）作为原子单元整体保留。

---

### 7. 无块级质量校验

**现象**：切完不检查过短块（<50 token 可能是噪声）、过长块（>1024 可能是解析失败）、乱码/OCR 错误。

**解决**：post-process 步骤——过滤近空块、合并过短块进前一块、标记过长块（打日志）。

---

### 8. 切分参数缺少实验验证

**现象**：512/64 是"感觉均衡"，没有 A/B 数据。

**解决**：新增 `scripts/benchmark_chunking.py`，实测 256/32 hit@1 仅 54.5%、512/64 为 86.4%、768/96 为 90.9%——**512/64 从此有数据支撑**。

**教训**：参数选择要用自己的语料跑实验，而不是拍脑袋。

## 三、架构类

### 9. ChromaDB 用嵌入式会导致多进程数据分裂

**现象**（若改嵌入式）：backend 和 Celery 两个进程各一份 `.chroma`，Celery 入库的文档后端搜不到。

**根因**：嵌入式数据跟着进程走，无法跨进程共享；强制共享同一目录会因 SQLite/HNSW 并发写锁冲突。

**解决**：用 Server 模式，两边通过 HTTP 连同一个服务端。详见知识库 `03_项目经验/01_本RAG项目架构设计.md`。

---

### 10. 前端生产构建 TypeScript 报错（dev 不报构建才报）

**现象**：`vue-tsc && vite build` 报 TS1016/TS2307/TS7053，但本地 `npm run dev` 一切正常。

**根因**：dev 走 Vite 不跑类型检查；缺 `env.d.ts` 导致 `.vue` 模块解析失败；可选参数排在必选前。

**解决**：补 `env.d.ts` 声明 `*.vue`；可选参数移到末尾；对象索引加类型断言。

**预防**：任何改动后跑一次 `npm run build`；CI 里加类型检查。

## 五、认证与工程类

### 22. 原生 fetch 不带 Authorization 头（登录后聊天仍 401）

**现象**：JWT 登录后，会话列表能加载（200），但发消息 401。

**根因**：`useStreaming.ts` 用原生 `fetch` 调 `/api/chat/completions`，没走 axios——axios 请求拦截器自动带 token 的逻辑对它不生效。

**解决**：fetch 的 headers 里手动补 `Authorization: Bearer <token>`。

**预防**：新增请求点先确认它走统一 client（axios 拦截器）；原生 fetch 要手动带头。

---

### 23. `.env` 加非 Settings 字段触发 pydantic extra_forbidden

**现象**：在本地根目录 `.env` 加 `HF_HUB_OFFLINE=1` 后，后端启动报 `Extra inputs are not permitted`。

**根因**：`Settings` 是 pydantic-settings，未声明 `extra="allow"`，`load_dotenv(override=True)` 把 .env 读进环境后，非字段变量被拒。

**解决**：本地根目录 `.env` 只放 Settings 字段；`HF_HUB_OFFLINE`、`ANONYMIZED_TELEMETRY` 这类非字段变量放 `run.bat` 里 `set`，或走容器 `env_file`（容器内无 `/app/.env`，不会触发）。

**预防**：分清"应用配置字段"（进 Settings/.env）与"环境变量"（走启动脚本或容器 env_file）。

---

### 24. 本地 chromadb 客户端版本被 pip 悄悄升级

**现象**：本地客户端变成 1.5.9、服务端仍是 0.6.3，创建集合报 `KeyError: '_type'`（服务端 500）。

**根因**：`requirements.txt` 锁 `chromadb==0.6.3`，但某次 pip 操作把它升了，本地与容器版本错配。

**解决**：`pip install "chromadb==0.6.3"` 降回；服务端从 requirements 构建不受影响。

**预防**：确认依赖与 requirements.txt 一致；`pip show chromadb` 检查。
